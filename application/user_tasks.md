# Пользовательские корутины `UserTask` и `Spawn`

`NCommon::UserTask<T>` — ленивая корутина C++23 с единственным владельцем, которую можно перемещать, но нельзя копировать. При создании выделяется и конструируется кадр корутины, а её параметры, передаваемые по значению, перемещаются или копируются. Тело при этом не исполняется. Защищённый метод `Application::Spawn(UserTask<T>&&)` возвращает `Job<T>` и немедленно ставит первое возобновление корутины в существующий `TaskSystem`.

```cpp
NCommon::UserTask<std::unique_ptr<int>> MakeValue(std::unique_ptr<int> input) {
    const std::stop_token stop = co_await NCommon::UserTaskStopToken{};
    if (stop.stop_requested()) {
        GRAPHICS_ENGINE_THROW(NCommon::EError::CANCELLED, "Value computation cancelled");
    }
    co_return std::move(input);
}

// Inside an Application subclass:
m_valueJob = Spawn(MakeValue(std::make_unique<int>(42)));
// Consume through the same IsReady/TryTake contract as RunAsync.
```

Поддерживаются типы результата `T`, `void`, значения с единственным владельцем и параметры по значению. Тип результата-ссылка запрещён. `unhandled_exception` сохраняет исходное исключение до его преобразования средой исполнения в обычную ошибку `Job`. Ошибки создания и выделения памяти выбрасываются синхронно. Попытки запустить недействительную, перемещённую или уже запущенную корутину выбрасывают `INVALID_STATE`. **Допустимая корутина считается потреблённой уже при попытке `Spawn`**, даже если последующее выделение памяти или допуск завершается неудачей. Уничтожение или замена ещё не запущенной корутины освобождает её кадр, приостановленный в начальной точке, без исполнения тела.

После `Spawn` существующая принадлежащая среде исполнения запись `UserJobScope` владеет кадром корутины через собственные данные исполняемой работы. Отдельного вычислительного исполнителя или самостоятельного времени жизни корутины нет. Кадр удерживается во время исполнения и ожидания других `Job`, а уничтожается после конечной приостановки или отмены приостановленной работы, **до** того, как результат становится видимым через `Job`. Типизированный `Job` хранит значение или ошибку независимо от кадра корутины и `Engine`. Уничтожение `Job` не отменяет работу; ошибки, результат которых никто не получил, сопровождаются существующим диагностическим сообщением.

Отмена работы, ещё находящейся в очереди, уничтожает её кадр на начальной приостановке без возобновления. Исполняющаяся корутина получает токен совместной остановки своего `Job` через запрос `co_await NCommon::UserTaskStopToken{}`, который всегда готов и не приостанавливает исполнение. Выполняющийся код C++ нельзя принудительно прервать или уничтожить. Отмена до окончательного завершения заменяет успешный результат на `CANCELLED`, а произошедшая ошибка сохраняется и остаётся доступной. `Stop()` прекращает допуск, отменяет ожидающие работы и дожидается выполняющихся до уничтожения владельцев среды исполнения. У каждого `Run()` собственная область задач; старые дескрипторы не могут запускать работу в новом `Run()`.

`co_await std::move(job)` доступен внутри `UserTask` и потребляет `Job` ровно один раз. Готовый результат извлекается сразу на текущем worker; если результат ещё не готов, корутина переходит в `WAITING`, освобождая worker. `T` перемещается в ожидающую корутину, `void` не возвращает значения, а `FAILED`/`CANCELLED` преобразуются в проектное исключение с исходными кодом и сообщением. Повторное ожидание потреблённого дескриптора даёт `INVALID_STATE`; ожидание lvalue и посторонние awaiters отклоняются при компиляции.

```cpp
NCommon::UserTask<int> AddOne(NCommon::Job<int> input) {
    const int value = co_await std::move(input);
    co_return value + 1;
}

// Inside an Application subclass:
m_valueJob = Spawn(AddOne(RunAsync([] { return 41; })));
```

Регистрация ожидания и публикация terminal результата синхронизированы одним mutex. Для каждого ожидания создаётся отдельная запись с weak owner; источник не хранит сырой адрес coroutine frame. Завершение помечает эту запись готовой и будит существующий диспетчер `UserJobScope`. Диспетчер публикует продолжение в TaskSystem только после возврата предыдущего `resume`; поэтому даже завершение прямо во время регистрации не допускает одновременных `resume`. Поздняя нотификация предыдущего ожидания не открывает следующее. Продолжение может попасть на любой worker пула; main thread не исполняет его, блокирующие worker waits и покадровый polling не используются.

Отмена `WAITING` или ещё не начатого продолжения уничтожает приостановленный кадр без дальнейшего исполнения пользовательского тела и публикует `CANCELLED`. Она не отменяет сам ожидаемый Job: его независимая работа и lifetime сохраняются. Отмена во время `resume` остаётся кооперативной; уничтожение возможно только после возврата этого `resume`. Ошибка постановки продолжения завершает ожидающую корутину с `OUT_OF_MEMORY` и освобождает кадр. При `Stop()` сначала закрывается admission и отменяются user jobs, затем дренируется их scope при ещё живом TaskSystem, после чего `WaitIdle` завершает executor tails. Результат старого `Run()` может лишь разбудить старую weak registration и не запускает работу нового поколения.

Длительные пользовательские вычисления продолжают занимать вычислительные потоки. Задачи и корутины не имеют зависимостей от кадров, слотов либо арен, даже когда запускаются из `OnUpdate()`. Для записи в `World` или изменения состояния основного потока требуется протокол доступа или команд соответствующего владельца: `Spawn` не предоставляет ни доступа к ECS, ни привязки к основному потоку.

Передавайте данные, которыми должна владеть корутина, **как параметры по значению**. Ссылки, указатель `this` у метода и объекты замыканий захватывающих корутин-лямбд остаются заимствованными и должны пережить выполнение. В частности, вызов временной захватывающей лямбды-корутины не переносит объект её замыкания в кадр корутины. Предпочтительны свободные или статические функции с параметрами по значению; метод объекта допустим, если сам владелец переживает завершение всех работ при `Run()`/`Stop()`. Реализация следует правилам C++ для начальной и конечной приостановок и времени жизни параметров: https://eel.is/c++draft/dcl.fct.def.coroutine.
