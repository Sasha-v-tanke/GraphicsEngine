# Документация GraphicsEngine

Документация организована по двум маршрутам: от задачи, которую нужно решить, и от публичного модуля, который требуется использовать.

## Решить задачу — `docs/how_to/`

В этом разделе размещаются пошаговые сценарии, объединяющие несколько подсистем движка. Каждый сценарий ведёт от ожидаемого результата через подготовку и последовательность действий к полному примеру, проверке результата, обработке ошибок и завершению работы.

**Запланированные сценарии** (пока не опубликованы):

- Первое приложение: настройка, окно, цикл обновления и вывод кадра.
- Пользовательская асинхронная система: планирование работы, доступ к данным и безопасная публикация результата.
- Загрузка ресурсов: запрос, ожидание готовности, ошибки и освобождение.
- Создание и изменение сцены: сущности, компоненты и системы.
- Подготовка и отображение сцены: снимок состояния, рендеринг и графический интерфейс.

## Изучить модуль — `docs/about/`

Здесь описываются назначение и публичные возможности отдельных модулей: когда ими пользоваться, как настроить, какие классы и методы доступны, что они возвращают и какие ограничения должен учитывать вызывающий код. Сведения о внутренней реализации здесь не дублируются.

**Запланированные описания** (пока не опубликованы):

- Application, Engine, Window и TaskSystem.
- ECS, Scene, Resources и Math.
- Renderer, RenderGraph и Graphics.

До появления пользовательских руководств технические сведения о текущей реализации доступны в README исходных модулей.

## Структура и навигация

- `docs/how_to/`: результат → предварительные условия → шаги с примерами API → полный рабочий сценарий → проверка → ошибки и варианты использования.
- `docs/about/`: назначение → быстрый старт → публичные возможности и методы → настройка → примеры → ошибки и ограничения → связанные сценарии.
- `<module>/README.md`: ответственность → зависимости и устройство → состояния и время жизни → потоки и синхронизация → ошибки и инварианты → проверка.

Пользовательские страницы связываются в обе стороны: сценарий ссылается на описания участвующих модулей, а описание модуля — на применимые сценарии. Из `docs/how_to/` для перехода в `docs/about/` используется относительный путь `../about/<имя>.md`; обратный переход — `../how_to/<имя>.md`. Ссылки на README реализации из обеих категорий имеют вид `../../<модуль>/README.md`.

Публикуются только ссылки на существующие страницы. Для каждого исходного модуля внутренние сведения сохраняются в одном корневом `README.md`; дополнительные Markdown-файлы внутри деревьев модулей не создаются. Отдельного `docs/api/` нет: публичные методы документируются в `docs/about/`.
