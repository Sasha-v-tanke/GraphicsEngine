# Сущность и доступ к компонентам

`NScene::Scene` владеет единственным `NEcs::World`. `Scene::CreateEntity(name)` возвращает копируемый `NEcs::EntityRef`: идентификатор World, слот, поколение и слабые признаки lifetime/системного scope. Фасад не хранит компоненты и не удерживает Scene или World. `World::GetEntityRef(EntityReference)` связывает существующую qualified identity с теми же проверками; это мост к legacy сущностям и внутренним обходам.

Создание возвращает pending identity. `IsPending()` означает неопубликованный create, `IsAlive()` до commit возвращает false. `AddComponent<T>(args...)` и `AddComponent<T>(T value)` поддерживаются одним variadic template и возвращают EntityRef по значению. Значение может быть move-only. Add, Remove и Destroy только записывают команды существующего strict intake. Дубликат Add или Remove+Add в одной epoch — ALREADY_EXISTS, отсутствующий Remove — NOT_FOUND. Destroy идемпотентен до commit. После запроса Destroy уже опубликованная сущность остаётся alive и её компоненты доступны до commit.

`GetComponent<T>()` возвращает T&, а const EntityRef — const T&. `TryGetComponent<T>()` возвращает соответствующий указатель; для отсутствующего или pending компонента — nullptr. `HasComponent<T>()` читает только опубликованную версию. Get для pending create выдаёт NOT_READY, для отсутствующего компонента — NOT_FOUND. Вызов методов компонента выполняется обычным C++: `entity.GetComponent<Health>().Damage(20)`. Неявных Replace, forwarding методов или отдельного Builder нет.

Имя — необязательный `NEcs::NameComponent::Value`: пустой аргумент не добавляет этот компонент, одинаковые имена разрешены. Имя не является GUID. Transform и другие компоненты автоматически не создаются. Создание имени и reservation публикуются в intake вместе: отказ allocation при подготовке не оставляет скрытую pending сущность.

В owner/quiescent фазе допустим прямой доступ к опубликованным компонентам. Система обязана объявить Read/Write; mutable Get/TryGet требует Write, const Get/TryGet и Has — Read либо Write. В scoped batch дополнительно проверяется entity/chunk scope, в том числе для отсутствующего компонента. EntityRef, созданный фабрикой внутри системного callback, привязан к этой invocation и отвергается после её завершения, ошибки или из другого потока. Ранее созданный host EntityRef внутри callback тоже проверяет текущие declarations: сохранённый дескриптор не обходит scoped-доступ.

Ссылки и указатели на компоненты нельзя сохранять за пределами разрешённой фазы/callback или structural commit. Слабый lifetime token обнаруживает уже уничтоженный World, но не заменяет владение: остановка сначала обеспечивает quiescence, затем уничтожает World. IsAlive/IsPending для пустого или expired World возвращают false; остальные операции отвергают expired/stale identity. Нарушение invocation scope выдаёт INVALID_STATE. Runtime jobs удерживают прежние Scene/World leases по существующему SystemRun-контракту.

`Scene::CommitPending()` — host-only convenience над World::CommitPending. Runtime автоматически публикует initialization перед systems и системные команды после quiescence. Создание Scene-сущностей в этом этапе предназначено для host initialization/offline фаз; полный пользовательский runtime/system creation capability относится к FEATURE-0087. Typed systems, range Query и enabled-фильтрация остаются отдельными этапами FEATURE-0083–0085. Legacy World API сохраняется на время миграции.
