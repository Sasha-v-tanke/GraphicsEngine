# Неблокирующее выполнение систем

`NEcs::NInternal::PrepareSystems(shared_ptr<World>, TaskSystem&, onFinished)` захватывает эксклюзивный run guard до построения графа и создаёт heap state с неизменяемым порядком, стабильными invocations, handles, dependency arrays, owner lease и completion sink. Callback registry принадлежит World. RunSystems(TaskSystem&) использует этот execution core через private borrowed lease и отдельный host completion; worker guard сохраняется. RunSystems() остаётся последовательной удобной обёрткой.

PreparedSystemRun — move-only владелец публикации. Получите SystemRun и свяжите cancellation до Start. Start разрешён один раз и может завершиться синхронно, включая пустой граф. Уничтожение незапущенного PreparedSystemRun завершает его CANCELLED. Уничтожение наблюдающего SystemRun не отменяет работу. TryGetOutcome не ждёт и не потребляет результат.

Начальный outstanding=1 удерживает публикацию. Перед каждым Submit регистрируется contribution; при отказе он откатывается. Принятые wrappers исполняются до retirement даже при ошибке: system exception сохраняется внутри run, downstream callbacks пропускаются. Runtime не вызывает TaskSystem::Cancel для скрытых handles и сохраняет пул до drain. Финальный Submit не нужен: последний участник выполняет commit/rollback и cleanup.

DeferredStructuralCommandBuffer получает ticket до передачи производителю и удерживает run/World до Submit или уничтожения буфера. Адрес invocation стабилен. Буфер, передаваемый за пределы system callback, должен соответствовать producer, объявленному через BeginDeferredStructuralPhase (включая нулевой EntityCreateCount). Submit после возврата системы кладёт batch в owning invocation; cancelled run всё равно потребляет буфер и уничтожает payloads при retirement. Ticket предоставляет только право собирать команды в этом буфере, не произвольный доступ к компонентам. Dynamic fan-out с mutable World вне объявленного протокола требует отдельной TaskGroup/access интеграции.

Terminal означает завершение всех nodes/tickets, deterministic merge, structural commit либо discard, очистку temporary payloads и снятие World guard/lease. Cleanup/destructors и completion sink исполняются вне coordination locks. Cancellation не откатывает in-place component writes и не прерывает running callback. Ошибка выбирается после quiescence: publication error, затем первая system error в graph.Order, затем cancellation. Commit/cleanup failure даёт FAILED; World после неуспешного commit/cleanup закрыт для нового execution до teardown. Ошибки cleanup не должны давать ложный COMPLETED.

Гарантии терминальных переходов `TaskSystem` определяются самим исполнителем, а не ECS-адаптером. Этот adapter не меняет generic executor protocol и не гарантирует безопасное принудительное завершение не возвращающегося пользовательского кода.
