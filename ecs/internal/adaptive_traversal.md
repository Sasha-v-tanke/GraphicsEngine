# Адаптивный обход иерархии

`AdaptiveBatchPlanner` — внутренний планировщик обхода `TopologySnapshot`. Он не выдаёт доступ к произвольным компонентам World: вызывающая сторона отдельно обеспечивает admission и footprints через AccessCoordinator либо исключительное владение данными. Пользовательский ECS API и вычисление transforms не входят в этот модуль.

`ScheduleTraversal(snapshot, roots, mode, operation, policy)` возвращает обычный `TaskGroupHandle`. Все корни должны быть живыми, принадлежать snapshot и задавать непересекающийся лес. Проверка ссылок и оценок стоимости выполняется до публикации первой задачи. Иерархия не копируется; на время работы удерживается существующий topology lease. План содержит только результаты, счётчики готовности и оценки стоимости, индексированные стабильными slots snapshot.

## Режимы и результаты

- `TOP_DOWN`: callback получает неизменяемый результат родителя; для выбранного корня — `nullptr`.
- `BOTTOM_UP`: callback получает результаты всех непосредственных детей в порядке topology siblings. Последний готовый ребёнок выполняет продолжение reduction итеративно; worker не ожидает других задач.
- `INDEPENDENT`: callback не получает parent/child results.

Callback возвращает владеющее значение произвольного типа. Один узел имеет ровно одного writer. Ссылки на входные parent/child results действуют только внутри callback; их нельзя сохранять или передавать detached jobs. Callback может исполняться параллельно с другими ветвями; внешние побочные записи требуют отдельного disjoint ownership и не откатываются при ошибке.

`TraversalOutput<T>` — одноразовый слот публикации. `TryAcquire(tasks)` выдаёт immutable `TraversalResults<T>` только после `COMPLETED`. До completion и после failure/cancellation доступ к staging results отсутствует. Полученный результат сохраняет старую Entity identity; повторно использованный slot с другой generation не совпадает с ним. TaskSystem должен оставаться живым при наблюдении группы/output. `RunSerial` даёт итеративный reference с теми же правилами результата и порядка зависимостей.

Topology lease и execution captures освобождаются до terminal publication группы. Готовые результаты сами по себе не удерживают topology. Планировщик и исходный World могут быть уничтожены во время обхода: snapshot владеет независимым hierarchy storage. Структурная публикация в ещё живой World запрещена до освобождения snapshot. Результаты, возвращаемые callback, должны владеть своими данными; сохранённая ссылка на компонент не становится access lease.

## Пакеты и стоимость

Пакет описывает диапазон siblings либо выбранных корней. Малые ветви объединяются; большой диапазон делится только при наличии независимого остатка и свободного packet budget. Однодетная цепочка обрабатывается итеративно одним пакетом без task-per-node. Динамические descendants используют `SpawnInGroup`; внешняя публикация закрывается через `SealGroup` после допуска первого пакета. `WaitGroup` разрешён только host-потоку.

Максимум активных/queued пакетов выбирается из количества узлов, worker count и верхней границы `MaxPacketsPerWorker`; при одном worker создаётся один пакет. Target учитывает общую оценку работы, `TargetPacketsPerWorker`, минимальное полезное время пакета, измерение первых callback каждого пакета и стоимость scheduling предыдущих запусков. `EstimateWork` — необязательная чистая функция положительной конечной относительной стоимости узла. Неверные значения/overflow отклоняются до исполнения. Feedback принадлежит planner, но текущий run владеет им независимо от lifetime planner.

Метрики: число посещённых узлов, число пакетов, пиковое число активных/queued пакетов, wall time внутри пакетов, время публикации задач и последний target в work units. Счётчики времени не являются эксклюзивным CPU profiler: время пакета включает его локальное scheduling. Оценка стоимости не меняет observable порядок parent/child зависимостей и sibling reduction.

Исключение callback/spawn переводит TaskGroup в failure; pending работа отменяется, running работа дренируется. Отмена кооперативная, проверяется между узлами и шагами reduction. Незавершённые результаты не публикуются. Ошибка допуска закрывает созданную группу и освобождает lease; отказ динамического spawn не теряет уже учтённых участников.

## Проверки производительности

`BM_AdaptiveTraversal/<shape>/<workers>/<iterations>` использует существующий benchmark runner. Shapes: 0 balanced, 1 star, 2 bamboo, 3 random, 4 skewed; workers=0 — serial reference, 1/4 — TaskSystem; iterations=0/10000 — мелкий/тяжёлый callback с неодинаковой стоимостью узлов. Время включает планирование и ожидание completion, создание World вынесено за измерение.

Локальный Release, AppleClang 21, 4096 узлов, медиана трёх повторов (это измерение, не переносимый порог):

| Shape | Serial, ms | 1 worker, ms | 4 workers, ms | Пакетов, 4 workers |
| --- | ---: | ---: | ---: | ---: |
| Balanced, heavy | 107.801 | 109.570 | 30.288 | 9 |
| Star, heavy | 107.827 | 107.832 | 30.683 | 13 |
| Bamboo, heavy | 108.318 | 108.243 | 108.221 | 1 |
| Random, heavy | 108.604 | 110.689 | 33.887 | 10 |
| Skewed, heavy | 108.352 | 111.248 | 30.800 | 13 |

На мелком callback serial занимал 0.078–0.144 ms, один worker — 0.107–0.170 ms; абсолютный overhead — примерно 25–35 µs на 4096 узлов. Для такого workload планировщик сохранял один пакет; ускорение не заявляется. Глубокая цепочка не имеет независимых ветвей и также не должна ускоряться от увеличения workers.
