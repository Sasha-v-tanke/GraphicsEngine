# Выборочный world transform resolver

`TransformResolver` — внутренний потребитель удерживаемой топологии, без новых
пользовательских API. `LocalTransform` принадлежит `TopologyState`; производный
`WorldTransformCache` принадлежит resolver. Локальная матрица и её `LocalRevision`
изменяются только в разрешённой фазе записи World. Никакие другие компоненты не
получают обязательных entity revisions.

## Расчёт и версии

`ScheduleResolve(topology, requiredEntities, tasks)` собирает объединение запросов
и всех их предков. Повторы устраняются; чужие, пустые и устаревшие дескрипторы
отклоняются до отправки задач. Resolver связан с одним World и допускает один
незавершённый расчёт. Разные resolver могут независимо читать одну топологию.

Выборка передаётся в `AdaptiveBatchPlanner` в parent-first порядке. Проекция
связей содержит только выбранные узлы: соседние невостребованные поддеревья не
посещаются. Для `BOTTOM_UP` проекция дополнительно читает direct sibling links
выбранных родителей, сохраняя topology order для некоммутативной reduction;
resolver использует `TOP_DOWN` и этого дополнительного прохода не делает. Рабочие задачи читают неизменяемый результат родителя и записывают
собственное значение. Разбиение идёт по независимым поддеревьям с ограниченным
числом пакетов; deep bamboo обрабатывается итеративно без рекурсии и worker Wait.

Узел stale, если отличается `AppliedLocalRevision`, `AppliedParent` или
`AppliedParentWorldRevision`. У stale узла пересчитывается матрица и увеличивается
его собственная `WorldRevision`. Первый stale узел после актуального родителя
является dirty root; его выбранные потомки видят новую parent revision. Отдельно
изменённый ребёнок проверяется даже при cache hit родителя. Локальная запись
никогда не обходит потомков ради invalidation. `KEEP_LOCAL` меняет edge stamp;
`KEEP_WORLD` дополнительно меняет local revision. Обе версии включают era;
исчерпание всей пары отклоняется до изменения состояния.

Cache хранит не более одного значения на слот сущности, проверяя также World и
поколение. Снимок результата содержит только текущую ancestor closure, поэтому
несколько последовательных view-запросов переиспользуют общий cache, но не
возвращают отсутствующие в текущем запросе объекты. Матрицы доступны через
`ReadResolved(tasks)` только после успешного `GetCompletion()`. Getter ничего
не вычисляет и не публикует. Сохранённые результаты неизменяемы, не удерживают
World и могут пережить его уничтожение, новые расчёты и повторное использование
entity slots.

## Отказ и время жизни

Все значения вычисляются в staging storage. После успешного завершения группы
продолжение проверяет результаты и заранее выделяет map nodes только для stale
значений. Затем единая секция публикации заменяет cache без выделений памяти.
Исключение или отмена не открывают частичный результат; предыдущий cache остаётся
доступен следующему расчёту. `TaskSystem::Cancel` не допускает отмену уже
исполняемого продолжения публикации. При отмене `GetCompletion()` ещё выполняющийся
обход следует отдельно завершить через `GetTraversal()` либо `WaitIdle()`.

Topology lease удерживается до retirement всех traversal callbacks, исключая
параллельное изменение local matrices/links. Отмена продолжения не освобождает
lease работающего обхода. TaskSystem должен пережить планирование, отмену и
наблюдение. Ошибка отправки продолжения также может оставить выполняющийся обход;
его освобождение гарантируется retirement callbacks, а не возвратом из Schedule.
Уничтожение facade resolver не отменяет отправленный расчёт.

## Извлечение и culling

Потребитель объединяет required entities всех views и включает предков камер и
объектов. До completion запрещено использовать новый результат. Для culling
required означает все кандидаты, чьи bounds ещё не гарантированно консервативны,
а не только видимые в предыдущем кадре объекты: иначе движущийся из-за родителя
объект может ошибочно остаться невидимым. Bounds строятся по матрицам завершённого
текущего запроса; если актуальных bounds нет, объект сохраняется кандидатом.
Отсутствующий объект в `ResolvedTransforms::Get()` вызывает ошибку, без fallback
к старой матрице. Старый immutable результат соответствует старому состоянию;
он не является доказательством актуальности в новом кадре.

Существующий Renderer использует плоский `TransformComponent` и не отбрасывает
объекты по hierarchy bounds. Его перевод на incremental extraction относится к
IMPROVE-0044. Здесь не вводится новый TRS↔matrix переход: affine hierarchy может
содержать shear, который нельзя корректно разложить в текущий render TRS.

## Стоимость и проверки

Closure строится за `O(C log C)` с map на C выбранных сущностей; матричные
умножения выполняются только для stale узлов. Cache-hit всё равно проверяет
stamps всей closure. Planner пока выделяет временный массив по максимальному
слоту World (`O(S)`), как и полный traversal; выборка не обещает O(C) памяти.
Это явно отделено от отсутствия обхода невостребованных поддеревьев.

Регрессии `TransformResolver.*` покрывают parent/child/both edits, независимый
stale child, cache hits, несколько views, 10k bamboo, reparent modes, переполнение
матрицы с неизменным опубликованным cache, отмену, lifetime и поколения.
`AdaptiveTraversal.*` проверяет исходный полный обход и его порядок reduction.
