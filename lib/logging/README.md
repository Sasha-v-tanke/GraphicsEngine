# Logging

`Logging` — backend-neutral synchronous журналирование для CPU-кода. `Logger` принадлежит приложению или зарегистрированному сервису; глобального экземпляра и service locator нет.

`LogRecord` владеет сообщением, категорией, полями и контекстами. Перед вызовом sink запись получает timestamp и монотонную sequence. Sink вызывается без внутреннего lock; исключение sink изолируется и увеличивает счётчик ошибок. Отсутствие sink допустимо.

Состояния: `CREATED -> RUNNING -> SHUTDOWN -> RUNNING`. `Shutdown()` и деструктор не выбрасывают, предварительно вызывают `Flush()` каждого sink. Изменение sink/configuration и lifecycle не должно пересекаться с уничтожением владельца; публикация потокобезопасна. Путь создаёт owned строковые данные, поэтому его нельзя вызывать из real-time audio callback.
