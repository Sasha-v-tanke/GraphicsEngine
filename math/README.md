# Математические типы

`Math` определяет принадлежащие движку типы значений, используемые в контрактах `World` и `Renderer`.

Публичные заголовки предоставляют только типы GraphicsEngine:

- `Vec2`, `Vec3`, `Vec4`;
- `Mat4`;
- `Quat`;
- `Transform`;
- дескрипторы проекций камеры.

GLM остаётся внутренней деталью реализации. Она используется через закрытые функции преобразования и не должна появляться в публичных заголовках `Math`, `World` и `Renderer`.

## Соглашения

В GraphicsEngine используется правосторонняя система координат мира:

- `+X` направлена вправо;
- `+Y` направлена вверх;
- направление взгляда вперёд соответствует `-Z`;
- `Cross(+X, +Y) = +Z`.

Матрицы хранятся по столбцам и умножаются на векторы-столбцы. `ComposeTransform()` последовательно применяет локальные масштабирование, поворот и перенос.

Глубина в пространстве отсечения соответствует соглашениям Vulkan: ближняя плоскость отображается в `0`, дальняя — в `1`. Функции построения проекции принимают углы в радианах.

## Предусловия и границы

Типы — значения без общего изменяемого состояния; вызывающий код координирует конкурентную запись собственных объектов. GLM подключён как закрытая зависимость [модуля](module.cmake). `Normalize` требует ненулевой конечный вектор/кватернион, `AngleAxis` — ненулевую конечную ось; корректные параметры проекции (`0 < VerticalFovRadians < π`, положительные aspect/near и far > near) и невырожденный базис `LookAt` обеспечивает вызывающая сторона. Функции `noexcept` делегируют вычисления GLM и не обещают проверку или исправление некорректного ввода. Проверки affine/finite/invertibility для hierarchy и камер принадлежат соответствующим потребителям.

`Transform` хранит TRS. Произвольная affine матрица может содержать shear и не обязана представляться этим типом без потерь; ECS/Renderer сохраняют такие матрицы напрямую.
